# Обновление данных дашборда «Встречи → Оплата»

Все данные захардкожены в `src/data/`. Чтобы их обновить, нужно прислать
выгрузки из Pipedrive (PDF — предпочтительно, CSV для оценок встреч).

## Что прислать — чек-лист

Каждая строка ниже — отдельная выгрузка из Pipedrive. Можно слать в любом
порядке; парные графики (встречи + продажи/повторные) удобнее слать вместе.

| # | Выгрузка (отчёт Pipedrive) | Что внутри | Период | Куда идёт |
|---|---|---|---|---|
| 1 | **Встреча → оплата по консультантам** | 2 графика на консультанта: «Встречи …» (дискавери) + «Продаж из встреч …» (фильтр **WON**) | окт'24 – тек. месяц | `consultants.js` → `meetings`, `sales` |
| 2 | **Горячие встречи** | «Горячие встречи …» + «Горячих продаж …» (фильтр **WON** + заявка/ивент/контент) | окт'24 – тек. месяц | `consultants.js` → `hotM`, `hotS` |
| 3 | **Встреча → повторные** | «Встречи …» + «Повторные из встреч …» (этап «вторая встреча, презентация оффера для ЛПР») | с 16.02.2026 | `secondMeetings.js` |
| 4 | **CSV оценок первичных встреч** | колонки: консультант, дата, 5 критериев (баллы) + итог | по датам в файле | `meetingQuality.js` |
| 5 | **Встречи для прогноза** (агрегат SG) | 3 графика: маркетинговые (=горячие) / холодные / все встречи; на 2-й стр. — продажи | окт'24 – тек. месяц | `meetings.js` → `HIST_HOT`, `HIST_COLD` |
| 6 | **Факт продаж по консультантам** (список сделок) | таблица сделок: **Won time**, Owner, Title, Deal value | янв тек. года – сегодня | `salesFact.js` → факт по месяцу закрытия |

Дополнительно: для новых консультантов, которых нет в основном отчёте
(например, недавно вышедших), обычно приходит отдельный 1-страничный PDF —
его данные добавляются к тому же консультанту.

### Отчёт #6 — требования к выгрузке

Это **таблица сделок**, а не график, поэтому у неё свои правила:

- **Обязательные колонки:** `Won time` (месяц закрытия сделки), `Owner`
  (продавший консультант), `Title`, `Deal value`.
- Колонка `Won time` — ключевая. Без неё выгрузка бесполезна: месяц продажи
  взять неоткуда.
- **Экспортировать в CSV или XLSX, а не в PDF.** PDF Pipedrive печатает
  таблицу «как на экране»: правые колонки уходят за край листа, а строки
  ниже видимой области обрезаются. Won time и Owner как раз крайние справа.
- Если возможен только PDF — перед печатью скрыть лишние колонки (оставить
  4 нужные), развернуть страницу в landscape и раскрыть список целиком.
- Фильтр: стадия **WON**, пайплайн **SG-сегмент**, период — с января
  текущего года (`THIS YEAR`).

Что делать с данными: сгруппировать по `Won time` (месяц) и по `Owner`,
получить продажи по месяцу **закрытия**. Это другая нарезка, чем в отчётах
#1–2, где продажи привязаны к месяцу **первичной встречи**. Обе нужны:
атрибуция к встрече показывает конверсию, атрибуция к закрытию — денежный
факт месяца и то, как быстро дозревают сделки.

## Важные детали выгрузок

- **Продажи = только стадия WON** (в фильтре отчёта должно быть `WON`).
- **Горячие** = фильтр `ЗАЯВКА (=ГОРЯЧАЯ), ИВЕНТ НОВЫЙ, КОНТЕНТ НОВЫЙ`.
  Холодные = все − горячие (отдельно слать не нужно, считается само).
- **Продажи привязаны к месяцу первичной встречи**, а не закрытия сделки —
  во всех графических отчётах (#1, #2, #5). Исключение — отчёт #6, там
  наоборот, месяц закрытия (`Won time`).
- **Последние 3 месяца не дозрели.** Сделка закрывается в среднем через
  ~3 месяца после первичной встречи, поэтому продажи трёх последних месяцев
  в отчётах #1/#2/#5 всегда занижены — это не ошибка выгрузки. На дашборде
  такие месяцы помечены как «дозревает».
- Отчёт #3 (повторные) — период только с момента появления этапа
  «вторая встреча» (16.02.2026), а не весь диапазон.
- Команда консультанта (MS1/MS2/MS3) берётся из префикса в заголовке графика.

## Как Claude извлекает данные (для исполнителя)

0. **Сначала текстом, не картинкой.** `pdftotext -bbox-layout file.pdf -`
   отдаёт слова с координатами — этого хватает и для таблиц, и для графиков
   (числа над столбцами кластеризуются по x). Рендер в PNG нужен только
   когда текстового слоя нет. Пачка страниц-картинок упирается в лимит
   размера запроса (32 МБ), текст — нет.
1. Если картинка всё же нужна: `pdftoppm -r 300 -png …`. Если poppler не
   установлен — `apt-get install -y poppler-utils`.
2. Резать каждую страницу на **полноширинные полосы** (W ≈ 2483 px при 300 DPI),
   отдельно заголовки графиков и области со столбцами — иначе обрезаются
   правые месяцы или числа.
3. **Порядок консультантов в разных отчётах может отличаться** — всегда
   считывать заголовок каждого графика, не полагаться на позицию.
4. **Проверки качества перед записью:**
   - горячие ≤ всего (по каждому месяцу и встреч, и продаж);
   - `HIST_HOT + HIST_COLD == все встречи` (помесячно) в отчёте #5;
   - продажи ≤ встречи;
   - таблица из отчёта #6 не обрезана: последняя строка целая, видны все
     4 колонки, число строк совпадает со счётчиком сделок в Pipedrive.
   Несостыковка обычно значит перепутанные графики (встречи/продажи) —
   перечитать заголовки.
5. **Обрезанные выгрузки не достраивать по догадке.** Если в файле не хватает
   колонки или строк — сказать об этом и попросить переэкспорт, а не
   восстанавливать значения из соседних отчётов.
6. После обновления: `npm run build`, затем закоммитить и запушить в рабочую
   ветку. Перед записью присылать пользователю извлечённые числа на сверку.

## Структура файлов данных

- `src/data/consultants.js` — массив `D`: `{ name, fullName, team, meetings, sales, hotM, hotS }`, ключи месяцев `"YYYY-MM"`.
- `src/data/secondMeetings.js` — `SECOND_MEETINGS`: `{ name, team, m1, m2 }` + `SM_MONTHS`.
- `src/data/meetingQuality.js` — `MEETING_QUALITY`: `{ c, t, d, s:[5] }` + `MQ_CRITERIA`, `MQ_MAX`.
- `src/data/meetings.js` — `HIST_HOT`, `HIST_COLD` (агрегат SG для прогноза).
- `src/data/salesFact.js` — `SALES_FACT`: `{ owner, month, title, value }`,
  месяц закрытия сделки (`Won time`). Пока не заведён — появится с первой
  корректной выгрузкой #6.

Если меняется горизонт прогноза — обновить `FORECAST_START` в `src/constants.js`
(первый месяц без факта).
